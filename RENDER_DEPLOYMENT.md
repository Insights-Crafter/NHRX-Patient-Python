# Deploy NHRX on Render

`render.yaml` defines the FastAPI service on the `deployment` branch. Cloudflare Pages hosts the static frontend, and Neon provides PostgreSQL.

- `nhrx-patient-api`: the FastAPI application, started on Render's assigned `$PORT`.
- Cloudflare Pages builds and serves the files in `frontend/`.
- Neon hosts the PostgreSQL database.

## Before creating the Blueprint

1. Commit and push the intended changes to the `deployment` branch.
2. Create a Render Blueprint from `https://github.com/Insights-Crafter/NHRX-Patient-Python` and select the `deployment` branch. The Blueprint creates the backend only.
3. In Neon, create or select a database and copy the **pooled** connection details. Set the prompted Render variables `DB_USER`, `DB_PASSWORD`, `DB_HOST`, `DB_NAME`, and `AES_SIV_KEY`. Use the hostname containing `-pooler` for `DB_HOST`, port `5432`, and preserve the existing `AES_SIV_KEY` if the database contains encrypted patient data. The Blueprint sets `PGSSLMODE=require` and `PGCHANNELBINDING=require`; `JWT_SECRET_KEY` is generated by Render.
4. Keep `CREATE_DB_TABLES=false`. Create or migrate the database schema deliberately before using the application; startup does not run migrations, and the repository's existing migration is not a complete fresh-database schema.
5. Create a Cloudflare Pages project from the same repository and select the `deployment` branch. Set the project root directory to `frontend`, build command to `python build_frontend.py`, and output directory to `dist`. Set the Pages build environment variable `API_BASE_URL` to the public HTTPS origin of the Render API (for example, `https://nhrx-patient-api.onrender.com`). Set `PYTHON_VERSION` to `3.13.3` if you want to pin the Pages build Python version.
6. After Cloudflare assigns the Pages URL, set the Render API's `CORS_ORIGINS` environment variable to that exact origin (for example, `https://your-project.pages.dev`) and redeploy the API. Add your custom domain origin too if you use one.
7. Open the Cloudflare Pages URL. The API health check is available at the Render service root `/`.

The Blueprint uses Render's Free plan for the API. Render may change plan availability or limits; choose a different plan in `render.yaml` if needed. Neon database provisioning is separate from this Blueprint.

## Local development

`frontend/config.js` defaults to `http://localhost:8000`. The Cloudflare Pages build creates a separate `dist/config.js` using `API_BASE_URL`; it does not overwrite the local configuration file.

Do not commit `.env` or put database credentials, encryption keys, or other secrets in `render.yaml`. Use HTTPS and synthetic data for initial checks. Review the privacy and security requirements before handling real patient information.
